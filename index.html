CloudFlow · serverless image processing on AWS

I built CloudFlow to understand how AWS services work together in a real application. A signed-in user uploads images, chooses a size and format, and gets resized files back. The API accepts the job in milliseconds, a queue holds it, a Lambda function does the work in the background, and the page shows the result when it is ready.

          Why asynchronous
          
            
            
              
          • 29 seconds. API Gateway cuts a request off at 29 seconds; resizing a batch can take longer, so the API only accepts the job and answers at once with an id.
            • 
              
          • Bursts. The queue absorbs a spike and the worker drains it at its own pace, instead of the front door falling over.
            • 
              
          • Retries. A message that fails is delivered again by SQS without the client doing anything; only repeated failures are parked.
            • 
            
          
          
          
          
          
            
          Request lifecycle
          
            
            
              
          1. Sign in The Cognito hosted page signs the user in with the authorization code flow and PKCE.
            2. 
              
          2. Upload POST /uploads returns presigned forms; the browser sends the bytes straight to the private input bucket.
            3. 
              
          3. Submit POST /jobs records the job and queues a small message.
            4. 
              
          4. Process The worker claims the job, resizes with Pillow, and writes the results.
            5. 
              
          5. Check and download GET /jobs/{jobId} returns the status and presigned links valid for five minutes.
            6. 
              
          6. Recover Three failed receives move a message to the dead-letter queue and raise an alarm; a corrupt image fails alone and is not retried.
            7. 
            
          
          
          
        
          
        
          
          
          What happens on failure
          Reliability demo · simulation
          
          
            
            
          1. Corrupt message (poison). The worker cannot find a job id, writes nothing, and reports the message; SQS redelivers it.
            2. 
            
          2. Rejected data. A well-formed job with invalid data is marked failed once and is not retried.
            3. 
            
          3. Temporary failure (transient). A write error marks the job failed and reports it; the retry completes it.
            4. 
            
          4. After three failed receives SQS moves the message to the dead-letter queue, a CloudWatch alarm goes to ALARM, and an alert is published to SNS.
            5.

            What I verified
            
          
            
          
            Two problems I found and fixed
            
          
            
            
            
              
            Bug 1Every submit returned 500
            
              
            
                
            Symptom
            Valid requests passed validation, then 500 Internal server error. Nothing reached the queue.
            
                
            Cause
            The API's IAM role trust policy carried an aws:SourceAccount condition. API Gateway does not populate that key when it assumes an integration role, so the assume-role call was refused. Found in the execution log.
            
                
            Fix
            Removed the condition from that one role; the Lambda roles keep it. Redeployed within the hour.
            
              
            
              Evidence 03 →
            
            
            
            
              
            Bug 2Download link answered 403
            
              
            
                
            Symptom
            Status said completed with a signed link, but fetching it gave 403 Forbidden after a redirect.
            
                
            Cause
            The link was signed for the legacy global S3 host. S3 redirected the us-east-2 bucket to its regional host; the signature covers the host, so it no longer matched.
            
                
            Fix
            Sign against the regional endpoint with SigV4; a regression test asserts the regional host. Verified: 200, zero redirects, byte-identical file, tampered signature refused.
            
              
            
              Evidence 08 →
            
            
          
            
        
            
        
            
          
            Security and reliability mechanisms
            
          
              
            
            • Cognito + PKCE. Sign-in on the hosted page with the authorization code flow; the browser never holds AWS credentials.
              • 
            
            • Presigned POST policy pins. Uploads are pinned to one key, one content type and a 1 byte to 5 MB size range, and the upload form expires after 60 seconds.
              • 
            
            • Per-user prefixes. Each user's inputs and results live under their own id; one user cannot list or read another's.
              • 
            
            • IAM per function, with a static test. Every Lambda has its own role scoped to exact actions and resources, and a test fails on a wildcard or on a policy outside the reviewed set.
              • 
            
            • Atomic claim + lease. A conditional write gives a job to one worker; a lease that expires lets another worker take over a dead one.
              • 
            
            • Per-file failures are never retried. A corrupt image fails alone with a short reason; the other files still finish.
              • 
            
            • Alarms + dead-letter queue. Three failed receives park the message and raise a CloudWatch alarm.
              • 
            
            • No secrets in the repository. Keys come from the environment or SSM Parameter Store; the public build and the CI pipeline scan for secret-shaped text and refuse to publish it.
